# Problem & Requirements

## Starting point

The project began with direct conversations with the business owner rather than a pre-written technical specification.

The high-level need was to create a stronger, more organized digital presence across three locations while keeping the system simple enough for local staff to follow.

## Requirements derived from the conversations

1. Present SayNinja as one recognizable brand across all locations.
2. Keep local accounts useful for neighborhood/community communication.
3. Centralize ownership and control of important digital assets.
4. Avoid turning location managers into full-time marketers.
5. Create a repeatable way to collect real photos and videos from all locations.
6. Reduce manual follow-up and make missing daily uploads visible.
7. Create a workflow that can support future locations.
8. Measure performance instead of relying on guesses.

## User constraint that changed the design

An early media-sharing design placed too much organizational work on Gym Masters.

That led to a simplified requirement:

> A Gym Master should only need to film, open one folder, and upload.

The system therefore moved complexity away from frontline staff and into centralized automation.

## Success criteria

The initial system should make it possible to answer:

- Did each location submit footage today?
- How many files were submitted?
- When was the latest upload?
- Can the owner see activity without changing files?
- Can the social lead select and reuse the strongest material?
- Can the process be repeated when another location is added?
